# AGENTS.md

Conventions for this repo — `CLAUDE.md` is a symlink to this file. Read it
before adding or changing a design.

## What this site is

`tayles.co.uk` is one page of content — the word **tayles**, a LinkedIn link
and a GitHub link — rendered through many different designs. A new design is
generated weekly; the newest is the homepage and every older one keeps its URL
at `/designs/<slug>` forever. **Designs are never edited or deleted once
merged** — they are a dated archive. Fix a design only if it is actually
broken.

## Anatomy of a design

```shell
src/designs/<slug>/
├── index.astro     the design
├── index.md        name, description, date, tags (+ the screenshot embed)
└── screenshot.webp generated by `bun run screenshots`, committed
```

`<slug>` is kebab-case and permanent — it is the URL.

Both files are required: `src/lib/designs.ts` throws at build time if one is
missing, so a half-scaffolded design fails CI rather than shipping.

### Hard requirements — every design must

1. Contain exactly one `<h1>` whose text is `tayles`.
2. Contain a link to `https://github.com/tayles` and one to
   `https://linkedin.com/in/tayles` — exact URLs, visible, keyboard-focusable,
   and **GitHub always first** in DOM order.
3. **Scope all CSS to its own root.** Never style bare `body`, `html` or `*`,
   and never use `is:global`. Set fonts on the design's own wrapper. The
   design renders inside `[data-design-root]`; the nav chrome, the gallery and
   the 404 page share the document with it.
4. Leave room at the bottom centre for the nav chrome (roughly `3.5rem` of
   bottom padding) so it never covers content.
5. Honour `prefers-reduced-motion: reduce` — disable or freeze every
   animation.
6. Work from 320px to 2560px wide with no horizontal overflow.
7. Produce zero console errors.

These are all asserted by `tests/designs.spec.ts`, which iterates the whole
collection — so a new design gets the full suite for free.

### What a design may do

Go as far as you like: canvas particle systems, WebGL/three.js, 3D CSS,
shaders, SVG filters, games. Any free-to-use asset (Unsplash, Pexels,
Wikimedia, public-domain textures, open icon sets) is fair game.

- **Prefer CDN-hosted assets and libraries** (jsDelivr, unpkg, cdnjs, Google
  Fonts) over committing files — the repo gains a design every week and must
  stay small. Load heavy libraries from a CDN inside the design so they never
  enter the shared bundle.
- Use **stable** URLs. `scripts/capture-screenshots.ts` fails loudly on a
  failed request rather than photographing a broken page.
- Record where an asset came from in the design's `index.md` body.
- Keep the page interactive within about a second on a mid-range laptop.
- An interactive design that wants the arrow keys must put
  `data-captures-keys` on the focusable element that uses them; the nav chrome
  yields to it while it has focus. `⌘K` / `Ctrl+K` always reach the command
  palette; a bare backtick does too, unless focus is in a text field.

## Conventions

- **Bun** for everything. Never `npm`/`pnpm`/`yarn`.
- **oxfmt** formats, **oxlint** lints (type-aware). `bun run check` checks
  everything, `bun run clean` fixes what it can. Single quotes, 80 columns,
  trailing commas, sorted imports.
- **Strict TypeScript** (`astro/tsconfigs/strictest`). No `any`, no
  `@ts-ignore`. TypeScript is pinned to 6.x because `astro check` needs the
  programmatic API that TypeScript 7 does not yet expose.
- `@/*` maps to `src/*`.
- Tailwind is for the **site chrome only** — the nav, gallery and 404 page.
  Designs use their own scoped `<style>` blocks, not utility classes.
- shadcn/ui components live in `src/components/ui/` and are only used by
  `DesignChrome.tsx`.
- Dates in `index.md` are plain `YYYY-MM-DD` and are formatted in UTC
  everywhere, so the rendered day never shifts with the build machine.

## Before you commit

```bash
bun run verify                     # check (fmt + lint + typecheck), build, test
bun run screenshots --only <slug>  # capture the new design
bun run designs:md                 # regenerate DESIGNS.md
```

CI runs the same steps via `verify:ci`, plus a check that `DESIGNS.md` is in
sync and that every design has a committed screenshot.

Note the ordering: `index.md` only gains its `![…](./screenshot.webp)` embed
once the screenshot exists, because Astro resolves that image at build time. A
brand-new design therefore builds fine before its first capture.
